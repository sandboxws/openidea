# This fork

`sandboxws/openidea` is a personal fork of [l0ng-ai/openidea](https://github.com/l0ng-ai/openidea).
It adds the Gruvppuccin themes and the PyIdea Python features, and merges upstream regularly.
Upstream moves fast (thousands of commits a month), so every fork change is built to merge cheaply:
new code lives in new places, and edits to upstream files are few, small and listed below.

## Where fork code lives

| What                    | Where                                                                                                                        |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Feature activation seam | `src/features/fork.ts` (workbench), `src/features/forkSettingsWindow.ts` (Settings window)                                   |
| Frontend features       | `src/features/{gruvppuccin,pyidea,python-tests,python-web,toml-workbench,mojo,scientific,spark}/`                            |
| Backend                 | `crates/ide-pyidea/` (domain logic), `crates/ide-host/src/ops/fork/` (commands)                                              |
| Plugins                 | `plugins/gruvppuccin/`, `plugins/mojo/`, `plugins/sparksql/` (never `plugins/official/`, which upstream signs and publishes) |
| Scripts                 | `scripts/fork/` (merge guard), `scripts/gruvppuccin/` (theme generator)                                                      |

Rules:

- Features never import each other. Fork features talk to upstream through hidden actions
  (`run.pluginStart`, `run.stopProcess`, `run.createConfig`, `diff.compareTexts`,
  `profiler.showCpuProfiles`), IPC commands and `@/editor/*` exports.
- Settings live in the free-form `settings.plugins.<namespace>` map (`gruvppuccin`, `pyidea`, `mojo`),
  with defaults in fork TypeScript, so `crates/ide-core/src/settings.rs` and the frontend settings
  schema are never edited. Per-project UI state goes in `localStorage`, keyed by project root.
- Backend per-project state lives in fork-owned maps keyed by project root, not in `Project`.
- Ids: actions `gruvppuccin.*`, `pyidea.*`, `pythonTests.*`, …; commands `pyidea_*`.
  Icons are registered with `registerExternalIcons` (`ext:fork/…`) instead of editing `src/ui/icons.tsx`.
  No default shortcuts (those would edit `src/platform/keymaps/`).
- New UI text goes in one contiguous fork block at the top of `src/platform/locales/text/en.json` and
  `zh.json`.

## Fork plugins

Fork plugins aren't signed or published; link them into the IDE from the repository:

```sh
cargo run -p ide-host --bin openidea-plugin -- link plugins/gruvppuccin
```

That links into the installed app's data. For a `pnpm tauri dev` instance, set `OPENIDEA_PLUGINS_DIR`
to `<app data>/ai.l0ng.openidea.dev.<worktree id>/plugins` first (`pnpm dev:status` prints the
identifier). The IDE asks once to trust an unsigned plugin.

- `plugins/gruvppuccin/`: 63 Gruvppuccin themes and the Gruvppuccin file icons, generated by
  `node scripts/gruvppuccin/generate.ts` from `data/palettes.json` (see its README). Its accent,
  preset, bold keyword and corner radius settings are the fork feature `src/features/gruvppuccin`
  (Settings › Appearance › Gruvppuccin).
- `plugins/mojo/`: the Mojo language (`.mojo`, `.🔥`; Python-style highlighting, comments,
  indentation) and the fire file icon. The SDK's language server, formatting, running and debugging
  are the fork feature `src/features/mojo`.

## Fork features

- **Gruvppuccin** (`src/features/gruvppuccin`, `plugins/gruvppuccin`): see above.
- **Python save actions, rule links, suppression completion** (`src/features/pyidea`,
  `crates/ide-pyidea`, `crates/ide-host/src/ops/fork`): Ruff's safe fixes and formatting on save
  (Settings › Tools › Actions on Save › Python, per project; explicit saves only, like upstream's save
  actions), a documentation link for each Python problem in the hover, and completion of codes in
  `# noqa`, `# ruff: noqa`, `# type: ignore[…]`, `# pyright: ignore[…]`, `# pyrefly: ignore[…]` and
  `# ty: ignore[…]` comments. Ruff comes from the project's environment, `languages.ruff.path`, managed
  tools or `PATH`; nothing is installed.
- **Python Tests** (`src/features/python-tests`, `crates/ide-pyidea/src/tests`, `crates/ide-pyidea/helpers`):
  a test explorer (left stripe) that collects pytest, unittest and doctest tests before running
  them, runs and debugs any group, shows failures with their source, parameter values, comparison
  and output, watches saves and external changes to run the related tests (import graph, mirrored
  test files, `conftest.py` subtrees), and runs doctests from the gutter or one example from the
  editor's context menu. The Python helpers are embedded and written to the data directory; test
  them with `PYTHON=<python with pytest> cargo test -p ide-pyidea -- --ignored`.
- **Python Web** (`src/features/python-web`, `crates/ide-pyidea/src/web.rs`):
  Flask Server, FastAPI Server (Uvicorn) and Django Server run configurations, without automatic
  reload, so Debug stops in request handlers. **Tools › Discover Web Applications** reads the
  project's files (nothing is imported) for Flask and FastAPI instances and factories, FastAPI's
  `[tool.fastapi]` entrypoint and Django's `manage.py`, and creates the chosen one's configuration,
  started from its own directory and importing from its `src/` layout. An empty interpreter means the
  project's: upstream swaps `python` and sets `PYTHONUNBUFFERED` only for its own Python kinds, so these
  types do both themselves.
- **TOML Workbench** (`src/features/toml-workbench`, `crates/ide-pyidea/src/toml`, `crates/ide-pyidea/schemas`):
  PyIdea's bundled schemas for `pyproject.toml` (with uv and Ruff settings), `uv.toml` and `ruff.toml`
  give taplo completion, hover and diagnostics offline. They are written to the data directory and
  associated in the global `languageServers.taplo.settings`; a user association for the same file wins,
  and **Use Bundled TOML Schemas** (`plugins.tomlWorkbench`) turns them off. **Tools › Find TOML
  Section** searches a TOML file's tables. Each `pyproject.toml` requirement shows its `uv.lock` and
  installed versions, and completes PyPI versions after a comparison operator.
- **Project Dependencies** (`src/features/python-deps`, `crates/ide-pyidea/src/deps`): **Tools › Open
  Project Dependencies** shows a `pyproject.toml`'s runtime dependencies, extras, dependency groups, uv
  dev dependencies and build requirements with their locked and installed versions, the lock's
  transitive packages and why each is installed. Add, edit, remove, move and upgrade requirements are
  staged (applied with `toml_edit`, keeping the file's formatting); **Preview Changes** resolves them
  with `uv lock` and `uv sync --dry-run` in a copy of the project (at most 20,000 files and 256 MiB;
  no symbolic links), shows the lock and environment changes and the file diffs, and **Apply and
  Sync** writes the reviewed files, unless they changed since, then runs `uv sync --locked` for the
  selected groups and extras in the Run tool window.
- **Mojo** (`src/features/mojo`, `crates/ide-pyidea/src/mojo.rs`, `plugins/mojo`): finds the project's
  Mojo SDK (Settings › Languages & Frameworks › Mojo, else `.venv`, `.pixi/envs/default`, the
  interpreter's environment) and, for a project with Mojo files, writes its project settings:
  `languageServers.mojo` (the SDK's `mojo-lsp-server` with the import paths and source roots) and
  `tools.lldb-dap.path` (a launcher for the SDK's `lldb-dap` that loads the Mojo LLDB plugin and
  formatters; upstream's `lldb-dap` adapter has no per-launch init commands). Mojo's own keywords are
  marked over Python's highlighting. **Mojo Application** configurations (▶ beside `main`; Run /
  Debug Mojo File) build with `-O0 -g` in a Before Launch command, then run or debug the binary;
  also **Build Mojo File**, **Reformat Mojo File** (`mojo format` on a copy), **Restart Mojo Language
  Server** and **Show Mojo Toolchain Status**.

## Edits to upstream files

Every edit to an upstream file is listed in `scripts/fork/touchpoints.json` with a budget of changed
lines. The merge guard fails on anything unlisted or over budget:

```sh
node scripts/fork/touchpoints.ts            # against upstream/main
node scripts/fork/touchpoints.ts <ref>      # against another base
```

| File                                     | Change                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------ |
| `src/features/index.ts`                  | imports `forkFeatures` and activates it after upstream's features              |
| `src/settingsWindowBoot.ts`              | imports `forkSettingsWindow` and activates it after upstream's pages           |
| `src/platform/locales/text/{en,zh}.json` | the fork's UI text, one block at the top of each catalog                       |
| `src/editor/lsp/hover.ts`                | `diagnosticRowDecorators`: lets a feature add to each problem row of the hover |
| `crates/ide-host/src/ops/mod.rs`         | declares `ops::fork` and lists its command domains                             |
| `crates/ide-host/Cargo.toml`             | depends on `ide-pyidea` by path                                                |
| `src-tauri/src/lib.rs`                   | `recursion_limit` 512: upstream's command catalogue sits at the 256 limit      |

## Syncing with upstream

One-time setup:

```sh
git remote add upstream https://github.com/l0ng-ai/openidea.git
```

Each sync:

```sh
git fetch upstream
git switch -c sync/upstream-$(date +%Y%m%d) main
git merge upstream/main
```

Resolve conflicts:

- `src/bindings.ts`, `src-tauri/tests/commands.snap`, `Cargo.lock`, `pnpm-lock.yaml`: take upstream's version, then regenerate
  (`pnpm gen:bindings`, `cargo update -w`, `pnpm install`). Never hand-merge them.
- Text catalogs: keep both upstream's entries and the fork block.
- A touch-point file: reapply the fork's few lines on top of upstream's version.

Then run `node scripts/fork/touchpoints.ts` and the checks CI runs for the parts that changed
(see `CLAUDE.md` › Before opening a PR), and open a PR from the sync branch into `main`.

## Toolchain notes

- `mise.toml` needs a recent mise. Without one, use Node 22 (`node --version` ≥ 22.22.2 on the 22.x
  line) and a Rust toolchain at or above the workspace `rust-version` directly.
- The fork's upstream-facing CI workflows (release, CNB mirror, plugin index) do nothing useful here;
  disable them on GitHub with `gh workflow disable <name> -R sandboxws/openidea` if they get in the way.
